# ADR-0002: 聚合层「真实链路优先 + 生成数据兜底」

- 状态: 已接受
- 日期: 2026-07-23
- 决策者: 平台架构

## 背景

项目初期没有真实 BMS/DCIM 采集器，但驾驶舱、暖通、电力等 22 个业务域页面必须可演示、可开发、可测试。同期又要求「接入真实采集器后不能推翻前端」。需要一个明确的数据源优先级与可观测标记。

```
MockCollector / Kafka / 真实 DCIM
  → POST /api/external/device/register + /metrics/upload
  → external_devices / metric_raws
  → dc_aggregator (35 个聚合函数)
  → 22+ 业务端点
```

## 决策

- `app/services/dc_aggregator.py` 为**唯一聚合出口**：先查真实链路，有数据则聚合返回并标记 `_source: "aggregated"`；无数据则调用 `dc_ioc_data.py` 生成器并标记 `_source: "generated"`。
- 所有业务端点只消费聚合层，不自行判断数据来源；前端在需要处展示来源标注。
- `DataSourceNotReadyError` 用于「声明为真实数据源但尚未就绪」的场景，返回 503 而不是伪装成生成数据（见 `main.py` 异常处理器）。
- 生产环境必须关闭 mock：`EXTERNAL_MOCK_COLLECTOR_ENABLED=false`。

## 备选方案

| 方案 | 优点 | 否决原因 |
|---|---|---|
| 前端各页面自行写 mock 数据 | 开发最快 | 接真实数据时要逐页重写；来源不可控，演示与生产行为分叉 |
| 全程只返回 mock，接入真实数据后一次性切换 | 逻辑简单 | 切换风险集中爆发，无法灰度，回归成本极高 |
| 无数据时返回空数组/404 | 语义最干净 | 演示与前端联调无法进行，空态掩盖接口缺陷 |

## 后果

### 正面
- 前后端可并行开发；真实采集器可按域逐步接入、灰度替换。
- `_source` 让「看到的是不是真数据」可观测，避免演示数据被误当生产事实。

### 负面 / 需承担的成本
- 生成器 `dc_ioc_data.py`（34 个函数、22 个业务域）需与真实数据结构持续保持一致，是一份长期维护负担。
- 聚合层成为单点，性能与缓存策略必须集中治理（dashboard 30s `cache_json`）。
- 必须持续防止生成数据流入生产报表：靠环境开关 + 启动密钥检查 + 来源标注三重保障。

### 后续动作
- 阶段二的全量 OpenAPI 契约把 `_source` 显式写进响应 Schema。
- 阶段三自动发现的「待确认区」沿用同一原则：发现结果绝不自动进入台账。
