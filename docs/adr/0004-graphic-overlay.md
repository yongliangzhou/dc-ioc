# ADR-0004: 图形编辑采用 JSON 场景覆盖层（Overlay）

- 状态: 已接受
- 日期: 2026-09-10
- 决策者: 前端架构

## 背景

12 个图形页（冷源工艺、制冷链路、温度云图、10KV/0.4KV 一次图、配电链路、柴发、储油、电池组、门禁平面、周界、消防平面）原本是「页面内写死坐标 + 接口数据」的只读渲染。需求是允许运维人员在页面上增删改节点、改名、改坐标、改参数，但**未编辑时渲染必须与原版逐像素一致**（这些图已验收，不能重画）。

## 决策

在 `graphic_config` 表中按 `kind` 存一份 JSONB「场景覆盖层」：

```json
{
  "nodes":   [{ "id": "...", "label": "...", "x": 0, "y": 0, "type": "...", "params": {} }],
  "edges":   [],
  "params":  {},
  "removed": ["node-id"]
}
```

合并规则（在 `useGraphicEditor.ts` 中执行）：

| 情况 | 语义 |
|---|---|
| 接口节点 + overlay 同 id 的字段 | **覆盖**（改名 / 坐标 / 参数） |
| id 出现在 `removed` | 删除 |
| overlay 有新 id | 用户自建节点 |
| 无 overlay / overlay 为空 | 直接渲染接口数据（与原版一致） |

- 端点：`GET/PUT/DELETE /api/ops/graphic-config/{kind}`；写操作限 admin/operator。
- 后端不可达时落 `localStorage` 并**显式标注**「本地草稿」，避免把草稿误认为已保存。
- 同一机制被阶段四复用于「可配置个人仪表盘」（`kind=dashboard`，payload 存布局顺序与显隐），不新增表。

## 备选方案

| 方案 | 优点 | 否决原因 |
|---|---|---|
| 把整张图（含全部节点）存数据库 | 模型直观 | 接口数据更新后用户存档会「冻结」旧结构；需重写 12 个页面的渲染源 |
| 每页单独建表存节点 | 类型严格 | 12 张表 + 12 套 CRUD，维护成本线性增长 |
| 只存用户新增节点，不允许改接口节点 | 最简单 | 不满足改名/改坐标的核心诉求 |
| 前端配置写死在代码里通过 PR 修改 | 无后端 | 运维人员无法自助编辑 |

## 后果

### 正面
- 12 个页面共用一套 `GraphicEditDrawer` + 一个表，新增图形页只需一个新 `kind`。
- 接口数据结构升级不会被用户草稿阻塞（缺失字段自动回落）。
- 天然支持「恢复默认」（删 overlay 即可）。

### 负面 / 需承担的成本
- overlay 与接口 id 强耦合：接口侧 id 变更会造成孤儿覆盖项，需要版本化或清理策略。
- JSONB 内容无强 Schema 校验，前端必须做防御式解析（非法结构回退空场景）。
- 离线草稿与服务端配置可能冲突，目前策略是「显式标注 + 手动重试」，未做自动合并。

### 后续动作
- 阶段四：为 `payload` 增加轻量 Schema 版本字段 `v`，便于未来结构演进。
- 图形页 id 变更时提供迁移脚本批量改写 overlay。
